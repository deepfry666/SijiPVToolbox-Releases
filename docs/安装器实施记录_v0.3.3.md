# 四季光伏工具箱 v0.3.3 安装器实施记录

- 文档版本：`v0.3.3-implementation.2`
- 目标版本：`v0.3.3`
- 记录日期：2026-08-26
- 状态：实现已写入源码，最终 EXE 与外部验收待冻结

## 变更范围

1. 兼容矩阵只把有完整 SDK、payload 和 CoreConsole 同哈希证据的 Series 标为
   `verified`；当前为 AutoCAD 2020 `R23.1`。旧版 `.NET Framework` 与新 `.NET 8`
   目标保留独立路径，不混装。
2. 安装器页面显示验证目标、每个宿主的 Series/Release、`acad.exe` 两种版本和
   `acdbmgd.dll` 版本，并显示明确的“可以安装/当前不支持”结论。
3. 不支持的宿主在兼容性页点击下一步时直接拦截；静默/命令行模式仍由
   `PrepareToInstall` 再次 fail-closed。
4. 正式产品继续使用稳定 AppId、ProductCode、UpgradeCode，并接受历史 `v0.2.0`
   ProductCode；未知同名 Bundle 永不覆盖。
5. 降级维护开关绑定 `IsTestBuild`，只可用于隔离安装器运行回归；正式/未签名本地
   测试版均不能用它绕过普通降级保护。
6. `.iss` 增加受控流水线预处理标记和模式门禁：没有流水线标记、没有 staging 输入，
   或正式模式没有 `SignToolName` 时编译立即失败；未签名模式必须在文件名和显示名中
   带 `TEST_UNSIGNED`。
7. `package-installer.ps1`统一传入目标标签和流水线标记，并继续记录源/staged/安装器
   签名分类、SDK provenance、输入文件哈希和 payload 哈希。

## 稳定产品身份

正式 `v0.3.3`沿用既有产品链，不因版本升级而更换身份：

```text
AppId        {0DB1FAD5-EC98-434F-8AF6-E16B3462A678}
ProductCode  {9C42F595-68E0-4945-B8D7-62BE70975D5F}
UpgradeCode  {7D31C7E3-7805-4611-9B3E-5946775A86EC}
Legacy       {5C2AE40B-D8F5-4025-B75E-13C0AEEB1251}
```

隔离测试使用独立身份和目录，不接管正式 Bundle。安装前备份、失败恢复、另一安装范围
迁移和卸载身份校验均在 Inno Code 段完成。旧 `v0.2.0` 没有当前 Inno AppId；迁移以
Bundle XML 身份为准。真实系统级旧版迁移尚未执行，不能用隔离测试代替该结论。

## 受控构建模式

| 模式 | `TestBuild` | `UnsignedDevelopmentBuild` | 是否允许无签名 | 输出位置 |
|---|---:|---:|---:|---|
| 隔离安装器测试 | 1 | 0 | 是 | `work/installer/test-v<version>` |
| 本机验收候选 | 0 | 1 | 是，但必须显著标识 | `work/installer/release-candidate-v<version>` |
| 正式公开版 | 0 | 0 | 否，必须可信签名 | 受控发布流程后才可进入 `outputs/` |

两种测试模式不能同时为 1。正式模式没有签名工具、允许签名指纹或可信时间戳时必须
失败关闭。测试版的文件名、Windows 文件属性、安装器首屏和随附说明都必须包含
`TEST_UNSIGNED`。

## 可追溯对象

每次候选构建至少保存：

- `build-result.json`：版本、模式、安装器哈希、payload 哈希、签名分类；
- `sdk-build-provenance.json`：目标 Series、SDK 版本、Autodesk 签名和输出哈希；
- `bundle-inventory.json`：manifest、源模块和 staged 模块的哈希链；
- `iscc-build.log`：Inno 编译输出；
- 纯代码、安装器静态/运行和 CoreConsole 验证日志；
- 版本化需求记录、安装说明、验证摘要、发布证据 JSON 和 `SHA256SUMS.txt`。

项目没有 Git 仓库，因此不得删除或覆盖 `work/legacy-source/v0.3.2`；新版只在当前
源文件和独立 `v0.3.3` 文档中记录，旧版文件保持历史只读。

## TEST_UNSIGNED 收口与延期边界

本轮把历史 `package.ps1`、`install.ps1`、`uninstall.ps1` 和四个中文 CMD 入口改为
立即失败，不能再绕过版本化 EXE 流程。安全回归在每次直接调用前后分别核对 `outputs/`
以及用户级、系统级正式 Bundle 的目录和文件哈希。AutoCAD 加载消息与 `JJJJ` 首页均
持续显示 `TEST_UNSIGNED 未签名测试版`，避免安装完成后丢失发布分类。

以下兼容性与正式发布事项未在本轮实现，不得写成已经验证：

- 固定 `{app}` metadata 目录的 ProductCode/UpgradeCode 或 AppId 所有权预检，以及卸载
  时保留安装器未跟踪的外来文件；
- 同一 AppId 在 HKCU/HKLM（含另一安装范围）的 `DisplayVersion` 参与最高版本判断，
  以及仅注册表存在较新版本时的降级拒绝；
- 正式签名后 payload 哈希与 `sdkValidation.outputSha256` 的两阶段 provenance 链，同时
  保留签名前构建锚点。

这些事项和对应负例测试完成前，不能冻结正式签名候选，也不能把相关 metadata 所有权、
registry-only 降级或正式签名追溯结论列为通过。
