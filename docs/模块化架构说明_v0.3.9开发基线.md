# 四季光伏工具箱模块化架构说明

本说明记录 `v0.3.9` 之后的开发基线。它是架构拆分记录，不代表已经替换
`outputs/` 中的正式 `v0.3.9` 安装包。正式发布建议使用下一版本号。

## 模块边界

| 程序集 | 职责 | 可独立修改 |
|---|---|---|
| `StructuralToolbox.dll` | 首页、导航、Palette、Ribbon、About、模块发现与加载 | 是 |
| `StructuralToolbox.Contracts.dll` | `IToolboxModule` 和导航契约 | 是，但变更需兼容所有模块 |
| `StructuralToolbox.Rail.dll` | 导轨命令、绘图、统计、设置和导轨页面 | 是 |
| `StructuralToolbox.Ballast.dll` | 配重命令、绘图、统计、设置和配重页面 | 是 |

主工具箱不直接引用导轨或配重实现。它扫描同目录程序集中的 `IToolboxModule`
实现，按模块声明生成首页入口和导航目标。导轨与配重互不引用，工作流状态由各自
模块保存。某个功能 DLL 缺失或加载失败时，壳仍能打开，并继续加载其他可用模块。

## 用户体验边界

- 安装和卸载仍只有一个 EXE，用户不需要分别安装功能模块。
- `JJJJ`、`STPVRAIL`、`STPVBALLAST` 等既有命令保持不变。
- 首页、左侧 Palette、功能页尺寸和操作流程保持不变。
- 第一次加载模块可能产生一次程序集解析开销，正常使用中没有可感知差异。
- AutoCAD 已加载 DLL 后不能可靠地覆盖该 DLL，因此本地更新后仍需完全重启
  AutoCAD 才能切换到新模块。

## 构建和验证

完整构建运行：

```powershell
& .\scripts\build.ps1
```

模块可分别构建：

```powershell
& .\scripts\build-contracts.ps1
& .\scripts\build-rail.ps1
& .\scripts\build-ballast.ps1
```

`build.ps1` 最终把四个 DLL 放入同一个 Bundle。`package-installer.ps1` 再把整个
Bundle 编译成一个 EXE。安装器清单、构建结果、运行测试和发布证据均记录四个 DLL
的文件名及 SHA-256；`payloadModules` 继续保留主 DLL 条目，仅用于兼容旧发布字段。

## 后续模块规则

新功能先建立独立项目和独立测试，稳定后再通过 Contracts 接入壳。模块不得直接引用
其他功能模块。需要位置、方向、边距、间距、偏移或构件关系等工程几何输入时，相关
页面必须同时提供同名符号示意图，并加入 DPI 和布局测试。

当前仍采用整体 EXE 更新。物理 DLL 已经具备分模块更新的基础，但在签名、版本依赖、
下载校验、失败回滚和 AutoCAD 重启协调机制完成前，不启用在线单模块更新。
