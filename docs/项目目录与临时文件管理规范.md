# 四季光伏工具箱项目目录与临时文件管理规范

本规范解决三个问题：新文件应该放在哪里、什么时候可以删除、哪些文件绝对不能由清理脚本处理。

## 一、当前整理结论

2026-08-27 整理前，项目目录约 `2.18 GiB`，其中 `work/` 约 `2.16 GiB`。主要占用来自
旧版 CoreConsole 隔离环境、真实图纸验证副本和诊断目录。这些文件均可通过源码、根目录只读
原图和验证脚本重新生成，不属于发布成果。

本次安全清理删除 `89` 个可再生顶层项，释放 `2,280,010,130` 字节；`work/` 从
`2207.52 MiB` 降至 `33.13 MiB`。剩余内容仅为受保护的 `work/legacy-output/`。

默认清理边界：

- 可以清除：`work/` 下除 `legacy-output/`、`keep/` 之外的全部内容；
- 自动保留：`work/legacy-output/` 和 `work/keep/`；
- 永不处理：根目录 DWG、`src/`、`scripts/`、`tests/`、`bundle/`、`docs/`、`outputs/`、
  `.git/` 和已安装的 AutoCAD Bundle；
- `.bak`、`.dwl`、`.dwl2` 虽被 Git 忽略，也不由项目清理脚本删除。AutoCAD 运行时尤其不能
  清理锁文件。

## 二、目录职责

| 路径 | 用途 | 是否进 Git | 保留规则 |
|---|---|---:|---|
| 根目录 | 项目配置、README、受保护的原始/基准 DWG | 是 | 不移动、不覆盖原始模板 |
| `src/` | 壳、Contracts、导轨、配重等正式源码 | 是 | 永久 |
| `scripts/` | 构建、测试、验证、发布和维护脚本 | 是 | 永久 |
| `tests/` | 自动化测试源码和小型、脱敏、稳定夹具 | 是 | 永久 |
| `bundle/` | 当前源码基线对应的六 DLL Bundle | 是 | 每次完整构建同步更新 |
| `docs/` | 架构、操作规范、版本实施和验证结论 | 是 | 永久；结论不能只留在日志里 |
| `outputs/` | 当前唯一正式可安装版本 | 是 | 只保留当前发布目录和正式 EXE |
| `work/module-builds/` | 模块编译暂存和原子提交备份 | 否 | 构建结束即可清除 |
| `work/tests/` | 测试编译物和运行结果 | 否 | 测试结束即可清除 |
| `work/installer/` | 候选包、隔离安装包和构建清单 | 否 | 发布或否决后清除 |
| `work/verification-v*/` | CoreConsole 隔离环境和图纸副本 | 否 | 结论写入版本文档后清除 |
| `work/real-drawing-verification-v*/` | 真实图纸验证副本 | 否 | 结论写入版本文档后清除 |
| `work/release-v*/` | 候选构建各步骤日志 | 否 | 发布记录和哈希入文档后清除 |
| `work/diagnostics/` 等 | 临时问题定位、反编译和探针输出 | 否 | 问题关闭后清除 |
| `work/legacy-output/` | 历史安装包和人工回滚材料 | 否 | 默认保护，人工审查后精简 |
| `work/keep/` | 尚未归档、明确要求暂留的临时材料 | 否 | 默认保护，但不是备份 |

`work/` 中的内容不受 Git 保护。真正需要长期保留的结论必须写入 `docs/`；需要正式交付的文件
必须进入 `outputs/`；需要长期保存但不适合入 Git 的原始图纸或恢复文件，应另行复制到项目外
的受控备份位置，不能依赖 `work/keep/`。

## 三、后续文件落点

### 新模块

- 正式代码：`src/StructuralToolbox.<Module>/`；
- 独立构建脚本：`scripts/build-<module>.ps1`；
- 独立测试：`tests/<Module>*Tests.cs` 或 `scripts/test-<module>.ps1`；
- 临时编译物：`work/module-builds/<module>/`；
- 稳定后才接入壳程序和六模块总构建。

### 图纸和验证材料

- 根目录原始 DWG 只读使用；所有脚本先复制到 `work/` 再操作；
- 可公开、脱敏且足够小的固定回归夹具才进入 `tests/fixtures/`；
- 客户生产图、恢复图和临时导出不得放入 `outputs/`；
- 新增真实图纸验证统一使用 `work/verification-v<版本>/runs/<时间戳>/` 或
  `work/real-drawing-verification-v<版本>/runs/<时间戳>/`。

### 版本和发布材料

- 候选：`work/installer/release-candidate-v<版本>/`；
- 隔离安装测试：`work/installer/test-v<版本>/`；
- 正式交付：`outputs/SijiPVToolbox_v<版本>_AutoCAD2020/`；
- 上一稳定版回滚包：`work/legacy-output/SijiPVToolbox_v<版本>_AutoCAD2020/`；
- 版本结论：`docs/安装器实施记录_v<版本>.md`、`docs/安装器验证记录_v<版本>.md` 和
  `CHANGELOG.md`。

同一版本号重建但哈希不同的候选不得长期并存。最终发布后应删除未发布候选，避免用户拿错包。

## 四、保留周期

| 时点 | 必须保留 | 可以清除 |
|---|---|---|
| 开发中 | 当前问题所需的最近一次日志和图纸副本 | 已失败且不再分析的旧 run |
| 候选验收中 | 当前候选、最新隔离安装结果、当前验证副本 | 更早候选和重复诊断目录 |
| 正式发布后 | `outputs/` 当前版、上一稳定回滚包、版本文档 | 候选、测试安装包、验证隔离环境、构建缓存 |
| 下一版本稳定后 | 当前版和新的上一稳定回滚包 | 更早历史安装包，确认外部备份后人工删除 |

`work/legacy-output/` 当前包含多个早期版本、恢复图和试验包，因此不纳入自动清理。后续应先把
有业务价值的恢复图复制到项目外备份，再只保留“上一稳定正式 EXE + SHA-256 + 对应说明”。

## 五、安全清理方法

先预览：

```powershell
& .\scripts\Clear-ProjectWork.ps1
```

确认列表后执行：

```powershell
& .\scripts\Clear-ProjectWork.ps1 -Apply
```

脚本只枚举 `work/` 的直接子项，删除前再次验证绝对路径，且固定保护 `legacy-output` 和
`keep`。它不会关闭 AutoCAD、不会删除根目录备份文件，也不会触碰 `outputs/`。

建议在以下时点执行：

1. 一个问题已修复且验证结论已写入文档；
2. 一个版本已正式发布并完成安装确认；
3. 开始下一版本开发前；
4. `work/` 超过 `1 GiB` 时。

## 六、每次发布后的整理清单

1. 确认 `outputs/` 只有当前版本正式 EXE；
2. 记录正式 EXE 和六个 DLL 的 SHA-256；
3. 确认上一稳定版回滚包可安装；
4. 把 GUI、CoreConsole、真实图纸和安装器验证结论写入对应版本 Markdown；
5. 删除同版本未发布候选和失败测试包；
6. 预览并执行 `Clear-ProjectWork.ps1 -Apply`；
7. 检查 `git status`，确保客户 DWG、`.bak` 和锁文件没有进入提交；
8. 单独提交并推送本次目录规范、脚本或发布记录变更。
