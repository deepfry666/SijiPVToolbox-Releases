# 开发入口与工作流

## 开始一个新功能

先在 [ISSUES.md](../../ISSUES.md) 登记需求或问题，再决定功能归属：

- 现有导轨、配重、更新行为：修改对应正式模块；
- 新的几何或 AutoCAD 能力：先建立独立 `src/StructuralToolbox.<Name>/` 项目；
- 只有独立核心和测试稳定后，才通过 `IToolboxModule` 接入主壳。

不要直接从 `outputs/` 或 `bundle/` 里的 DLL 反推实现，也不要把不同日期的 DLL 手工拼进安装包。

## 日常循环

```powershell
# 1. 修改源码
# 2. Windows PowerShell 5 下跑完整回归
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1

# 3. 需要检查当前版本一致性时
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-ReleaseReadiness.ps1 -Version 1.0.8 -Phase Source
```

如果回归失败，先修复测试入口或记录中的问题，不要跳过失败项继续打包。

## 按模块选择验证

| 修改内容 | 最低入口 |
|---|---|
| 壳、首页、模块加载、DPI | `scripts/test.ps1`，再做 AutoCAD 2020 人工界面检查 |
| 导轨核心 | `scripts/test.ps1`，必要时 `scripts/verify-real-drawing.ps1` |
| 配重核心 | `scripts/test.ps1`，再用固定 DWG 副本检查识别、生成和删除 |
| 更新逻辑 | `scripts/test.ps1` 和 `scripts/update-service/Test-UpdateSite.ps1` |
| 独立模块 | 对应 `scripts/build-*.ps1`、`scripts/test-*.ps1`，稳定后再接入总构建 |

## 候选构建和发布

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-ReleaseCandidate.ps1 `
  -Version 1.0.8 `
  -AutoCADDir "D:\cad\AutoCAD 2020" `
  -RunInstallerRuntimeTest
```

候选只写入 `work/installer/release-candidate-v<版本>/`。完成 AutoCAD、安装器和人工界面验收后，才运行 `Publish-TestRelease.ps1` 写入 `outputs/`。

每次完成一组相关改动后都要：

1. 更新 `ISSUES.md` 的状态和验证证据；
2. 运行相关测试；
3. 单独提交 Git；
4. 推送远端；
5. 再开始下一组改动。

## 不要改动的东西

- 根目录原始 DWG；
- 已发布版本的 Bundle 和安装包，除非正在执行明确的发布流程；
- 历史版本文档中的结论；
- `work/legacy-output/` 中的上一稳定回滚材料。
