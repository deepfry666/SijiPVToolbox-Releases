# 四季光伏工具箱 v0.3.3 安装与兼容性说明

- 软件版本：`v0.3.3 TEST_UNSIGNED`
- 程序集版本：`0.3.3.0`
- 发布类型：`TEST_UNSIGNED` 未签名测试版（仅限本机验收，不得公开分发）
- 记录日期：2026-08-26
- 项目根目录：`<项目根目录>`

## 先看结论

本版本按“检测宿主版本后决定是否安装”的策略工作。当前只有 AutoCAD 2020 Win64
`R23.1` 完成了 SDK 对应、同哈希 CoreConsole 数据库运行验证，可以进入当前安装包。
AutoCAD 2018、2019、2021-2024 仍是 `.NET Framework` 候选；2025-2026 是独立
`.NET 8` 候选。候选版本不会被当前 Bundle 强行加载，也不会因为安装器识别到它就显示
“可以安装”。

本机正在运行的旧版本与新建版本必须分开表述：当前系统级安装若仍为 `v0.2.0.0`，
本文件只把 `v0.3.3`称为“新建测试版”，不能写成已经安装或已经切换。

## EXE 安装步骤

1. 保存图纸，完全关闭 AutoCAD、探索者和 `accoreconsole.exe`。
2. 打开 `outputs/SijiPVToolbox_v0.3.3_AutoCAD2020_TEST_UNSIGNED`。
3. 双击 `四季光伏工具箱_Setup_v0.3.3_TEST_UNSIGNED.exe`。
4. 在兼容性页查看“本安装包已验证目标：AutoCAD 2020 R23.1”。只有宿主显示
   `【结论：可以安装】`时，才能点下一步；不匹配宿主会显示 `【结论：当前不支持】`，
   且下一步会被明显阻止。
5. 全新安装通常选择“仅当前用户”。要迁移系统级旧安装时，选择“所有用户”并同意
   UAC；安装器会先校验并备份属于本产品的旧 Bundle，再执行替换。
6. 安装完成后启动或重启 AutoCAD，在命令行输入 `JJJJ`。

`TEST_UNSIGNED` 可能触发 SmartScreen“未知发布者”。这是预期的未签名测试状态，只
用于本机验收。正式公开 EXE 必须由受信证书签署安装器、卸载器和全部 payload，并带可信
时间戳；当前发布定义的签名指纹列表为空，所以正式构建会失败关闭，不会伪装成正式版。

## 宿主检测规则

安装器对每个注册到的 AutoCAD 宿主显示并核对：

- 注册表 `Series` 与 `Release`；
- `acad.exe` 是否存在，以及固定 `FileVersion` 和产品 `ProductVersion`；
- `acdbmgd.dll` 是否存在及其版本；
- Series 是否在当前已验证 payload 清单中。

固定版本字段被第三方环境改写时，只要产品版本仍与 Series 相符，身份检测可以继续；
任一必要字段缺失、互相矛盾或只是候选 Series，都显示“当前不支持”。安装器不修改
`SECURELOAD` 或 `TRUSTEDPATHS`。

## 升级、降级与回滚

正式产品沿用稳定身份，保证未来 EXE 更新仍属于同一产品链：

| 身份 | 值 |
|---|---|
| 正式 Inno AppId | `{0DB1FAD5-EC98-434F-8AF6-E16B3462A678}` |
| 正式 Bundle ProductCode | `{9C42F595-68E0-4945-B8D7-62BE70975D5F}` |
| Bundle UpgradeCode | `{7D31C7E3-7805-4611-9B3E-5946775A86EC}` |
| 接受的旧版 ProductCode | `{5C2AE40B-D8F5-4025-B75E-13C0AEEB1251}` |

安装器只迁移 ProductCode/UpgradeCode 属于本产品的 Bundle；同名但身份陌生的目录会停止，
不会覆盖或删除。普通安装禁止降级；`/ALLOWDOWNGRADE=1` 现在只在隔离安装器测试
Bundle 中有效，正式安装器即使收到该参数也仍然拒绝降级。备份后任一步失败会恢复原
目录，避免半升级。

旧 `v0.2.0` 是命令/脚本复制 Bundle 的版本，没有当前 Inno AppId 卸载登记；升级识别
依赖 Bundle 内的 ProductCode/UpgradeCode，而不是假设旧版已有 EXE 记录。自动化目前
验证了身份规则和隔离升级逻辑，真实系统级 `v0.2.0 -> v0.3.3` 仍需人工验收。

## 直接编译限制

`SijiPVToolbox.iss` 不是可直接双击编译的发布入口。源码要求由
`scripts/package-installer.ps1`传入受控流水线标记、经过校验的 staging/inventory、
兼容矩阵和目标标签；正式模式还必须传入签名工具。直接运行 `ISCC.exe` 会在预处理阶段
失败。未签名模式还在预处理器中强制文件名和显示名包含 `TEST_UNSIGNED`，避免产生一个
外观像正式版但没有发布证据的 EXE。

## 兼容性与追溯边界

兼容矩阵、SDK 文件版本/签名、源 DLL、staged DLL、实际加载 DLL、CoreConsole 日志、
安装器 EXE 和发布文件都通过 SHA-256 链接。复杂实图验证使用同一冻结源码编译的
内部 `FourJTools.RealDrawingVerify.dll` 执行 `STPVRAIL`；正式
`StructuralToolbox.dll` 在该步骤只做版本、SHA-256、MVID、build-result 和源码指纹
绑定，没有被 NETLOAD，也没有执行其 CAD 命令。发布证据必须保留这条边界，不能把
内部验证写成“正式 DLL 已在复杂实图执行”。没有 Git 仓库时，版本快照保存在
`work/legacy-source/`，发布目录只保留当前版本的 EXE、说明、验证摘要、证据 JSON 和
`SHA256SUMS.txt`。这些哈希证明文件一致性，不等于代码签名。
