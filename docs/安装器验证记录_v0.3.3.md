`Publish-TestRelease.ps1` 从冻结候选和版本化源文档创建 EXE、`安装说明.md`、
`验证摘要.md`；`New-ReleaseEvidence.ps1` 只生成证据 JSON 和 `SHA256SUMS.txt`，并
要求前三项已经存在。发布回执、runtime 回执和纯代码日志均按版本与 SHA-256 绑定；
纯代码日志还必须且只能包含一项 `REGRESSION_SUITE_SHA256`，其值覆盖当前
`scripts/**` 和 `tests/**`（排除 `bin/obj`）。证据生成和归档创建都会现场重算，任一
脚本或测试变化均使旧纯代码日志失效。任何一步失败都不能复用旧版本日志、哈希或
run 目录。

复杂实图步骤固定检查 3520 个组件、1760 条导轨、842 个标注组和 2326 个尺寸。其
执行程序集是同源内部 `FourJTools.RealDrawingVerify.dll`；正式
`StructuralToolbox.dll` 只做 SHA-256/MVID/build-result/源码指纹绑定，不能把该步骤
表述为正式 DLL 自身执行了复杂实图命令。

## 必须观察的新增门禁

- 直接执行 `ISCC.exe scripts/installer/SijiPVToolbox.iss` 在预处理阶段失败；
- 正式模式未提供 `SignToolName` 时编译失败；
- 未签名模式若文件名或显示名不含 `TEST_UNSIGNED`，预处理阶段失败；
- 兼容性页写出“本安装包已验证目标：AutoCAD 2020 R23.1”；
- 没有可安装宿主时，兼容性页下一步被阻止，命令行/静默安装也在准备阶段停止；
- `/ALLOWDOWNGRADE=1` 只在 `TestBuild=1` 的隔离安装器中有效；
- 候选输出文件名、文件属性和说明均包含 `TEST_UNSIGNED`，且签名状态为 `NotSigned`。

## 2026-08-26 发布追溯链加固记录

本轮只修改源码、脚本、测试、文档和 `work/` 审计材料；没有移动或改写
`outputs/`，没有运行真实 DWG，也没有生成最终发布目录。

已实施的追溯约束：

- 发布回执先在 `work/publish-v0.3.3` 暂存并自校验，发布目录移动成功后才原子
  提交；回执提交失败时，发布目录回移并清理；
- 发布证据 JSON 与 `SHA256SUMS.txt` 先在 `work/release-evidence-staging`
  生成，已有控制文件通过 `File.Replace` 和独立备份更新，任一提交失败时两项均
  尝试恢复；
- runtime 回执固定记录发布版本、冻结 build-result/EXE、测试 build-result/EXE、
  已安装载荷系列和已安装 DLL SHA-256；
- 归档创建器重新解析 pure-code、artifact、runtime 和 publish 回执，绑定版本、
  源码指纹、回归套件指纹、build-result、EXE 与唯一 `R23.1` 载荷；复制完成后再从
  归档内的 `files/src/StructuralToolbox`、`files/scripts` 和 `files/tests` 重算两项
  指纹，防止复制过程中的内容变化；
- `v0.3.3` 归档强制 schema 2 manifest、schema 5 release evidence、
  `releaseControls` 和发布目录校验清单；归档目录叶名称必须等于清单中的规范化
  `v<major.minor.patch>`，从而不能在 `v0.3.3` 目录中伪装成旧 schema；旧
  `v0.3.2` schema 1 冻结归档仍可复验；
- 发布目录在证据生成、归档生成和独立归档复验三个阶段均只允许顶层文件，不允许
  子目录或未被发布级 `SHA256SUMS.txt` 约束的递归载荷；
- 发布证据双控制文件的暂存写入失败、证据已替换后失败，以及归档移动后复验失败
  均有实际故障注入测试；测试检查旧控制文件恢复、目的目录撤回以及暂存目录无残留；
- 真实图归档保留 run 内层校验清单引用的隔离 `rail-settings.xml`，避免归档后出现
  清单引用文件缺失；
- 发布门禁新增 `BACKGROUND_GEOMETRY_FILTER=PASS`，防止背景线、多段线或块内几何
  被误当成尺寸避让障碍的回归。

## 本轮 TEST_UNSIGNED 收口边界

当前源码要求三个历史 PowerShell 入口和四个中文 CMD 入口直接返回失败，并在每次调用
前后核对 `outputs/`、用户级正式 Bundle、系统级正式 Bundle 均未变化。UI 回归还必须
同时看到 AutoCAD 启动消息和首页 `ReleaseClassification` 标签中的
`TEST_UNSIGNED 未签名测试版`。本轮只运行这些聚焦静态/UI 检查，不运行真实安装器、
不关闭 CAD，也不改写 `outputs/`。

固定 metadata 目录所有权、卸载保留外来文件、跨 HKCU/HKLM 的 AppId
`DisplayVersion` 降级判断，以及正式签名后 payload 哈希的两阶段 provenance 均为后续
阻断项。本记录不把它们列为通过；对应隔离负例和静态门禁完成后，才可更新候选结论。
