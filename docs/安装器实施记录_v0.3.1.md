# 四季光伏工具箱 v0.3.1 安装器实施记录

## 实施目标

- 用一个Inno Setup 6单文件EXE完成安装、升级和卸载。
- 默认当前用户安装；需要多人共用或迁移系统级旧版时可切换全用户安装。
- 检测本机AutoCAD，并严格区分“核心运行已验证”和“候选”；GUI验收单独记录。
- 对陌生同名目录、运行中CAD、降级和失败写入采取失败即停或回滚。
- 为后续正式签名、更新和多版本payload建立可审计边界。

## 已实现行为

统一构建入口为`scripts/package-installer.ps1`，Inno源文件和版本定义位于
`scripts/installer/`。稳定的AppId、ProductCode、UpgradeCode、旧版ProductCode和
允许签名者指纹集中保存在`release-v0.3.1.json`。

- 从64位HKLM/HKCU Autodesk注册表检测AutoCAD，并验证`acad.exe`存在。
- 安装界面显示核心运行已验证、候选和不支持状态；没有核心运行已验证宿主时停止安装。
- 检测`acad.exe`和`accoreconsole.exe`；运行中禁止安装、升级和卸载。
- 当前用户目录为`%APPDATA%\Autodesk\ApplicationPlugins`；全用户目录为
  `%ProgramFiles%\Autodesk\ApplicationPlugins`。
- 同时存在用户级和系统级安装时停止，防止AutoCAD重复加载。
- 迁移前校验ProductCode/UpgradeCode；陌生同名目录不覆盖、不删除。
- 更新前原子改名备份旧bundle；失败恢复，成功后清理。
- 普通降级被禁止；维护降级参数不出现在公开入口。
- Windows“已安装的应用”登记标准卸载入口。
- 升级和卸载默认保留`%APPDATA%\StructuralToolbox`设置。
- 不修改`SECURELOAD`、`TRUSTEDPATHS`或DWG文件。

## 多版本结构

`bundle/manifest-template/compatibility-matrix.json`是兼容状态唯一清单。
`New-MultiVersionBundle.ps1`只打包状态为`verified`且存在实际DLL的目标，每个Series使用
精确的`SeriesMin=SeriesMax`：

- AutoCAD 2018-2024：`Contents/Windows/Legacy/<Series>/`，.NET Framework。
- AutoCAD 2025及以后：`Contents/Windows/Net8/<Series>/`，.NET 8。

当前仅AutoCAD 2020（R23.1）具有payload和同哈希 CoreConsole 运行证据；其完整 GUI、
探索者交互和系统级升级仍待验收。2018、2019、2021-2026均为候选，不进入当前
manifest。扩展时必须取得相应SDK、生成独立模块，并分别记录核心运行与 GUI 验收证据。

## 构建分级

- 隔离测试：`package-installer.ps1 -TestCurrentPayload -FrozenBuildResult <候选build-result>`，
  使用独立身份和目录，且不重新编译候选payload。
- 本机验收：`package-installer.ps1 -AllowUnsignedDevelopmentBuild`，只允许输出到`work/`，
  EXE、源DLL和staged DLL必须全部为`NotSigned`。
- 正式发布：必须提供payload签名脚本和Inno签名命令；允许签名者指纹列表不得为空。

正式签名构建流程：

1. fresh build生成源DLL。
2. 调用payload签名脚本；调用前后校验脚本自身SHA-256不变。
3. 校验源DLL签名有效、签名者在白名单且存在可信时间戳。
4. staging并校验源/staged DLL逐字节一致，再校验staged签名。
5. Inno生成并签署EXE/卸载器。
6. 校验最终EXE签名、允许签名者和时间戳；DLL与EXE必须使用同一证书。
7. 任一步失败均不写成功build-result。

当前`allowedSignerThumbprints`为空，这是有意的失败关闭状态：本机可生成明确标识的
`TEST_UNSIGNED`包，但在配置真实发布证书前不能误生成`SignedAllowed`正式包。

## 追溯与发布证据

`build-result.json`使用schema 4，记录：

- 源码指纹和关键构建输入SHA-256；
- manifest、inventory、源/staged DLL和EXE哈希；
- 每个payload的year、Series、运行时和签名元数据；
- AutoCAD SDK程序集版本、SHA-256、Autodesk签名、构建profile及运行时家族；
- `payloadOrigin`及冻结候选build-result/候选EXE绑定；
- 签名分类、证书主题/颁发者/指纹/序列号/有效期和时间戳证书；
- verified/candidate Series集合。

`New-ReleaseEvidence.ps1`还要求：

- AutoCAD验证必须使用`-SkipReleaseBuild`测试已打包的同一DLL；
- 从原始CoreConsole日志重新提取唯一成功marker且禁止失败marker；
- 实际加载Assembly.Location、SHA-256、MVID与source/staged payload一致；
- CoreConsole版本对应Series、Autodesk签名有效；
- matrix、manifest、inventory、build和runtime五方Series集合完全相等；
- 纯代码、候选静态和冻结payload安装运行三类日志均具有最终成功标记；
- 公开证据使用项目相对路径，不公开项目根目录或实际安装路径；
- 用户交付目录严格只有EXE、安装说明、验证摘要、发布证据和`SHA256SUMS.txt`
  五个顶层文件。

## 当前边界

- 隔离当前用户安装、同版本升级、失败回滚、降级阻止和卸载已自动通过。
- 本机系统级`v0.2.0 -> v0.3.1`需要关闭CAD后由用户执行管理员验收。
- 当前交付为未签名本机测试版，不得作为正式软件对外分发。
- 最终候选EXE自身尚未执行系统级安装；自动运行回归使用独立产品身份安装同一冻结
  payload，并逐文件核对哈希。
- 实际在线更新服务不在`v0.3.1`；后续应下载完整签名EXE，校验SHA-256与发布者，
  等待CAD退出后调用同一安装器。
