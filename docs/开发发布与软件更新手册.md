# 四季光伏工具箱开发、发布与软件更新手册

本手册面向第一次维护 AutoCAD 插件的开发者。目标是让每次修改都能回答四个问题：

1. 修改的是哪个模块，是否越过了模块边界；
2. 五个正式发布 DLL 是否来自同一份源码和同一版本；
3. 安装包是否经过了与修改范围相匹配的验证；
4. 用户当前加载的版本是否真的已经切换到新构建。

## 一、当前结论

| 环节 | 当前状态 | 说明 |
|---|---|---|
| 模块独立开发 | 已建立 | 壳、Contracts、导轨、配重、更新是五个正式项目；支架大样保留为未发布的独立项目 |
| 多模块汇总构建 | 已建立 | `build.ps1` 每次统一编译并汇总五个正式 DLL |
| Bundle 文件集和哈希 | 已建立 | 安装器构建记录五个正式 DLL 的来源、版本和 SHA-256 |
| 安装升级和失败回滚 | 已建立 | 旧 Bundle 先改名备份，安装失败自动恢复 |
| 安装范围迁移 | 已建立 | 阻止用户级和系统级同时残留两份插件 |
| 用户设置保留 | 已建立 | 设置在 `%APPDATA%\StructuralToolbox`，不随卸载删除 |
| 普通降级保护 | 已建立 | 正式安装器阻止用旧版本覆盖新版本 |
| 一键候选构建 | 已建立 | 候选只进入 `work/`，不会自动发布 |
| 发布前版本体检 | 已建立 | 检查源码、五个正式模块、Bundle、安装包和已安装副本 |
| 代码签名 | 未建立 | 当前 EXE 和 DLL 都是 `NotSigned` |
| 在线更新基础 | 已建立 | HTTPS 清单、完整 EXE 下载、大小和 SHA-256 校验已建立；正式服务待 ICP、DNS 和 HTTPS 部署 |
| 完整 GUI 自动化 | 未建立 | Ribbon、Palette、选择集、预览和交互仍需人工验收 |

当前最合理的软件更新方式是“完整 EXE 原位升级”。当前版本按已接受的未签名分发方案
交付；无论是否签名，都不启用在线 DLL 热更新，也不在绘图过程中静默安装。

## 二、五个发布模块怎样协作

```text
StructuralToolbox.Contracts.dll
        ↑           ↑          ↑             ↑
      壳程序       导轨模块     配重模块        更新模块
        │                                      │
  首页、Palette、Ribbon、模块发现          HTTPS 清单与完整 EXE
```

- `StructuralToolbox.Contracts` 只放稳定接口和导航契约，不放业务算法。
- `StructuralToolbox` 只负责壳和模块加载，不直接引用导轨或配重实现。
- `StructuralToolbox.Rail`、`StructuralToolbox.Ballast` 和
  `StructuralToolbox.Update` 互不引用。
- `StructuralToolbox.SupportDetail` 源码和独立测试保留，但从 `v1.0.0` 起不进入正式构建、
  Bundle、安装器或主界面；重新接入前必须作为新功能重新验收。
- 新功能先做成独立项目和独立测试，稳定后再实现 `IToolboxModule` 接入首页。
- Contracts 一旦修改，必须视为五个发布模块共同修改，全部重编、重测、重打包。

禁止手工从不同日期的 `bin/` 目录复制 DLL 拼安装包。正确汇总入口只有：

```powershell
& .\scripts\build.ps1 -AutoCADDir "D:\cad\AutoCAD 2020"
```

该脚本按 Contracts、壳、导轨、配重、更新的依赖顺序构建，并将同一源码快照产生的
五个 DLL 放入 Bundle。安装器随后重新核对文件名、程序集版本和 SHA-256。

## 三、一次正常迭代的完整路径

### 1. 开始修改前

- 确认目标版本，例如 `1.0.1`。
- 明确受影响模块和图纸对象兼容性。
- 不修改根目录原始 DWG；验证只使用 `work/` 中的副本。
- 不在 `outputs/` 中调试；`outputs/` 只放已经完成验收的当前安装包。

版本号建议：

- 修复错误、不改变主要工作流：增加补丁号，例如 `0.4.0 -> 0.4.1`；
- 增加新功能或新模块通常增加次版本号；
- 命令、图纸元数据或 Contracts 出现不兼容变化：增加主版本号。

### 2. 独立开发和测试

| 修改范围 | 最少验证 |
|---|---|
| Contracts | 五个发布模块完整构建、模块隔离测试、所有功能回归 |
| 壳/Ribbon/Palette | 首页、模块缺失降级、Ribbon 恢复、DPI 和首次打开 |
| 导轨 | 纯算法、真实 DWG 副本、预览确认/取消、旧对象替换、统计 |
| 配重 | 纯算法、阵列识别、特殊覆盖、生成/删除保护、统计、示意图 |
| 支架大样 | 任意角度、可变组件/支墩、参数回读编辑、固定详图、DPI 和实图重开 |
| 在线更新 | 本地清单、HTTPS 限制、版本比较、大小和 SHA-256、后台检查、断网提示 |
| 安装器 | 全新安装、同范围升级、跨范围拦截、失败回滚、卸载、设置保留 |

工程几何输入涉及方向、边距、间距、偏移或构件关系时，必须同时提供同名符号示意图
和 DPI/窄宽布局测试。

### 3. 先做发布前体检

```powershell
& .\scripts\Test-ReleaseReadiness.ps1 -Version 1.0.1 -Phase Source
```

该命令会阻止以下常见错误：

- 五个发布 AssemblyInfo 版本不一致；
- Bundle、首页、About、README、测试版本漏改；
- 版本发布定义或三个版本文档缺失；
- 导轨和配重发生直接项目引用；
- 兼容矩阵把没有 DLL 的宿主标为已验证；
- 通用打包、证据脚本仍引用旧版本。

### 4. 生成候选，不直接发布

```powershell
& .\scripts\Build-ReleaseCandidate.ps1 `
  -Version 1.0.1 `
  -AutoCADDir "D:\cad\AutoCAD 2020" `
  -RunInstallerRuntimeTest
```

候选构建执行：源码体检、纯代码回归、五模块 SDK 构建、Bundle 体检、安装器构建、
安装器文件集核验；加上 `-RunInstallerRuntimeTest` 后还会进行隔离安装、升级、回滚和
卸载测试。所有结果进入 `work/`，不会改变正式交付目录。

候选安装包和 `build-result.json` 位于：

```text
work/installer/release-candidate-v<版本>/
```

### 5. AutoCAD 验证

CoreConsole 验证：

```powershell
& .\scripts\verify-autocad2020.ps1 `
  -Version 1.0.1 `
  -AutoCADDir "D:\cad\AutoCAD 2020"
```

导轨实图验证必须传入原图路径，但脚本只操作 `work/` 中的复制品：

```powershell
& .\scripts\verify-real-drawing.ps1 `
  -InputDwg ".\结构卷竣工图-项目.dwg" `
  -AutoCADDir "D:\cad\AutoCAD 2020" `
  -CandidateDll ".\bundle\ZhStructureToolbox.bundle\Contents\Windows\R23.1\StructuralToolbox.dll" `
  -CandidateBuildResult ".\work\installer\release-candidate-v1.0.1\build-result.json"
```

CoreConsole 通过只代表数据库和命令核心运行通过，不代表 GUI 已验收。至少还要人工检查：

1. `JJJJ`、Ribbon 和 About 显示正确版本；
2. 首页能打开导轨、配重和更新模块，且没有支架大样入口；
3. 导轨预览、确认、取消和旧对象替换；
4. 配重识别、按排设置、特殊阵列覆盖、生成和保护性删除；
5. 两类统计表；
6. 更新页与首页连续往返不改变用户设置的 Palette 外框尺寸；
7. 100%、125%、150%、200% DPI 和窄面板滚动；
8. 保存、关闭、重新打开图纸后对象仍正确；
9. AutoCAD 完全重启后加载的是新 DLL，而不是旧缓存。

配重模块目前有纯代码和 UI 测试，但还没有与导轨同等级的真实 DWG 自动运行验证。
以后对配重做高风险修改时，应保留一份固定的配重验收图和预期结果，补齐对应命令探针。

### 6. 提交、发布和归档

候选验收通过后，先提交并推送源码、Bundle DLL、发布定义和文档。确认该提交在远端可用后，
再执行正式发布：

```powershell
& .\scripts\Publish-TestRelease.ps1 `
  -Version 1.0.1 `
  -BuildResult ".\work\installer\release-candidate-v1.0.1\build-result.json"
```

发布脚本会把旧版安装包移入 `work/legacy-output/`，并确保 `outputs/` 只保留当前版本。
发布完成后立即运行 `Published` 体检：

```powershell
& .\scripts\Test-ReleaseReadiness.ps1 -Version 1.0.1 -Phase Published
```

体检通过后，只提交并推送本次正式 `outputs/` 产物及对应发布记录。这样源码构建提交与正式
交付产物提交相互独立，任何发布失败都不会污染已经验证过的源码基线。
不要手工删除历史安装包；至少保留上一稳定版用于人工回滚。

发布后记录 Git 提交、安装器 SHA-256、五个 DLL 的 SHA-256、签名状态、自动测试结果、GUI
验收人和日期。需要完整审计包时，再运行 `New-ReleaseEvidence.ps1`、
`New-ReleaseArchive.ps1` 和 `Test-ReleaseArchive.ps1`。

## 四、用户怎样升级软件

当前升级步骤：

1. 保存所有图纸；
2. 完全关闭 AutoCAD、探索者和 AutoCAD Core Console；
3. 使用与旧版相同的安装范围。旧版在“为所有用户”时，新版也选择“为所有用户”；
4. 运行新版本完整 EXE；
5. 启动 AutoCAD，输入 `STABOUT` 和 `JJJJ`；
6. 用安装体检比较已安装 DLL 与交付 DLL 的 SHA-256。

```powershell
& .\scripts\Test-ReleaseReadiness.ps1 -Version 1.0.1 -Phase Installed
```

安装器的安全边界：

- AutoCAD 正在运行时停止安装，不强制杀进程；
- 先完整备份旧 Bundle，再写入新 Bundle；
- 安装失败时恢复旧 Bundle；
- 不覆盖 ProductCode/UpgradeCode 不属于本产品的同名目录；
- 阻止用户级、系统级同时存在两份插件；
- 普通正式安装不允许降级；
- 卸载只删除安装器拥有的 Bundle，不删除用户 XML 设置。

版本号相同不代表二进制相同。候选重建后即使仍叫 `1.0.1.0`，SHA-256 也可能变化。
因此发布记录必须区分“当前安装版本”“新建候选版本”和“最终交付哈希”。

## 五、回滚方式

自动回滚只覆盖“安装过程中失败”。如果新版本安装成功但业务功能有问题：

1. 保存图纸并关闭 AutoCAD；
2. 从“应用和功能”卸载当前版本；
3. 安装 `work/legacy-output/` 中上一稳定版本；
4. 启动 AutoCAD，核对 About 和 DLL 哈希；
5. 如果新版本修改了图纸对象格式，先确认旧版能否读取，再打开生产图纸。

正式安装器禁止直接降级是正确的安全策略。不要为了方便删除这个保护。

## 六、在线更新的部署边界

AutoCAD 已加载的 DLL 不能可靠覆盖，所以当前实现只下载完整安装器，不直接复制 DLL。
独立更新模块和 GitHub Release 发布链已经完成以下基础能力：

- HTTPS `stable.json` 固定产品/稳定通道身份；
- 清单记录版本、文件大小、SHA-256、下载地址、日期和更新说明；
- 安装包先下载到用户本地临时更新目录，再核对大小和 SHA-256；
- 用户主动确认并完全退出 AutoCAD 后运行完整安装器；
- `stable.json` 和版本化 EXE 作为 GitHub Release 资产公开，不需要自建下载服务器；
- 发行脚本会阻止 HTTP 地址、清单哈希错误和下载链接错配，并在公开 Release 前下载回验。

正式发行仍必须完成：

- 断网、磁盘满、下载损坏、安装失败的回滚；
- 稳定版和测试版通道隔离；
- 用户主动确认，不在绘图过程中静默安装；
- GitHub 保留上一稳定版本、tag 和安装器资产的能力。

当前阶段已经接受 EXE 和 DLL 以 `NotSigned` 状态分发，代码签名不作为发布阻塞项。
GitHub 不可达时更新页只报告失败，不影响其他模块。SHA-256 能发现下载损坏和清单/文件
错配，但如果清单和安装包同时被替换，
它不能代替数字签名。可信代码签名、时间戳和可验证的清单签名保留为后续安全增强项。

## 七、容易忽略但必须长期管理的事项

1. **图纸数据兼容**：XData、块属性、图层和对象格式变更要有读取旧版数据的策略。
2. **设置迁移**：XML 新增字段要提供默认值；删除或改名字段要考虑旧设置文件。
3. **命令兼容**：已经交给用户的命令名不要随意改名，可保留兼容入口。
4. **Contracts 兼容**：接口变化等同于所有模块共同升级，不能只换一个 DLL。
5. **崩溃诊断**：错误信息要包含模块、命令和阶段，但日志不得收集用户图纸内容。
6. **代码签名**：当前按已接受风险保持 `NotSigned`；将来具备条件时再配置可信证书和时间戳。
7. **依赖来源**：新增第三方 DLL 时记录许可证、版本、下载来源和 SHA-256。
8. **AutoCAD 年份**：候选年份不等于支持；每个 Series 必须单独构建和运行验证。
9. **备份与恢复**：保留上一稳定 EXE、发布证据、Git 标签和对应源码。
10. **最小发布范围**：不要把测试图、日志、PDB、SDK DLL 或临时脚本放入安装包。
11. **安装范围**：用户级与系统级不可并存，否则 AutoCAD 可能加载错误副本。
12. **版本真实性**：About、文件版本和目录名一致仍不够，最终以 SHA-256 判断构建。

## 八、日常最短操作清单

开发中：

```powershell
& .\scripts\test.ps1
& .\scripts\build.ps1
```

准备候选：

```powershell
& .\scripts\Test-ReleaseReadiness.ps1 -Version <版本> -Phase Source
& .\scripts\Build-ReleaseCandidate.ps1 -Version <版本> -RunInstallerRuntimeTest
```

验收后发布：

```powershell
& .\scripts\Publish-TestRelease.ps1 -Version <版本> -BuildResult <build-result.json>
& .\scripts\Test-ReleaseReadiness.ps1 -Version <版本> -Phase Published
```

安装后确认：

```powershell
& .\scripts\Test-ReleaseReadiness.ps1 -Version <版本> -Phase Installed
```

安装确认后，按[项目目录与临时文件管理规范](项目目录与临时文件管理规范.md)先预览，再运行
`scripts/Clear-ProjectWork.ps1 -Apply` 清除候选、隔离环境和重复验证副本。

任何一个阶段出现 `BLOCK` 都不要继续发布；`WARNING` 必须在验证记录中解释。
